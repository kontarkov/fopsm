# Задание 1 — локальный GitLab и GitLab Runner

## Цель

Развернуть GitLab локально с помощью `Vagrantfile` и инструкции из учебного репозитория, создать новый проект с пустым репозиторием, зарегистрировать для него `gitlab-runner` и запустить runner в режиме Docker.

## Порядок выполнения и команды

**Статус: WIP — выполнение не подтверждено.** Следующие действия — план, а не журнал выполненных команд.

1. Уточнить URL учебного репозитория с `Vagrantfile`, изучить инструкцию, требования к памяти, диску, виртуализации и сетевому доступу.
2. Проверить доступность Vagrant и совместимость выбранной виртуальной среды. До подтверждения параметров `Vagrantfile` не запускать создание VM.
3. Развернуть GitLab по официальной инструкции, проверить доступ к интерфейсу и создать проект с пустым репозиторием.
4. Зарегистрировать runner именно для созданного проекта и настроить его работу через Docker. Токены регистрации и другие секреты не публиковать.
5. Проверить, что runner отображается в настройках проекта и доступен для запуска заданий.

```bash
# Диагностические команды перед развёртыванием (пока не выполнялись):
vagrant --version
docker --version

# Команда запуска допускается только после проверки Vagrantfile:
# vagrant up
```

**Контроль:** в интерфейсе GitLab должен быть виден runner, зарегистрированный для нужного проекта. Наличие установленного Docker само по себе не подтверждает работу runner.

# Задание 2 — репозиторий и GitLab CI/CD

## Цель

Отправить репозиторий в созданный GitLab-проект, изменив `origin`, и создать `.gitlab-ci.yml` с необходимыми этапами CI/CD. Подтвердить успешные сборки скриншотами.

## Порядок выполнения и команды

**Статус: WIP — выполнение не подтверждено.** Команды ниже — план последующей практики; адреса и ветку необходимо проверить до отправки.

1. Проверить локальный репозиторий, текущую ветку и удалённые адреса:

   ```bash
   git status
   git branch --show-current
   git remote -v
   ```

2. Сохранить возможность отправки отчёта на GitHub. После подтверждения URL созданного GitLab-репозитория изменить `origin`, проверить новые адреса и отправить текущую ветку:

   ```bash
   # Только после проверки текущих remote и согласования адреса GitLab:
   # git remote set-url origin <URL-РЕПОЗИТОРИЯ-GITLAB>
   # git remote -v
   # git push -u origin <ТЕКУЩАЯ-ВЕТКА>
   ```

3. Изучить содержимое учебного проекта и определить необходимые этапы CI/CD. Официальное условие не задаёт конкретные имена этапов и команды сборки.
4. Создать в корне репозитория `.gitlab-ci.yml`, проверить его синтаксис и соответствие исполнителю runner.
5. Создать коммит с конфигурацией, отправить изменения и проверить фактические результаты pipeline в GitLab.
6. После успешных запусков сделать скриншоты сборок. Если pipeline завершился ошибкой, сохранить реальный результат для диагностики, не обозначая его как успешный.

**[ДОБАВИТЬ ПОСЛЕ СОЗДАНИЯ И ПРОВЕРКИ]**. Содержимое будет определено по реальному учебному проекту и фактическим настройкам runner. Проверенного файла пока нет.
