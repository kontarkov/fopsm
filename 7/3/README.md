## Выполнение

1. Установлен и проверен Terraform.
2. Выполнены `terraform init`, `terraform fmt`, `terraform validate`, `terraform plan` и `terraform apply`.
3. Через Docker-провайдер созданы образы и контейнеры:
   - Nginx (`nginx:1.21.1`) — `127.0.0.1:1080 → 80`;
   - WordPress (`wordpress:latest`) — `127.0.0.1:2080 → 80`.
4. Проверена работа сервисов: Nginx ответил `HTTP 200`, WordPress перенаправил на страницу первичной настройки. Полноценная настройка WordPress и базы данных не выполнялась.
5. Через `terraform console` исследованы значения `var.containers`.
6. Через провайдер `random` создан ресурс `random_password.any_uniq_name` длиной 16 символов.
7. Через провайдер `local` создан `/tmp/xxx.txt` с правами доступа `0600`. Секретное содержимое файла не выводилось в отчёт.
8. Команда `terraform state list` подтвердила наличие шести управляемых ресурсов.
9. Создан контролируемый *configuration drift*: контейнер Nginx вручную переименован через `docker rename`.
10. `terraform plan` обнаружил изменение имени и предложил пересоздание контейнера: `1 to add, 0 to change, 1 to destroy`.
11. После `terraform apply` Nginx восстановлен с исходным именем и новым идентификатором; ответ сервиса — `HTTP 200`.
12. Финальная проверка `terraform plan` завершилась сообщением: `No changes. Your infrastructure matches the configuration.`

## Проверка результата

В каталоге с `.tf`-файлами:

```bash
terraform init
terraform fmt -check
terraform validate
terraform plan
terraform state list
```

В выполненной лабораторной работе итоговый `terraform plan` не обнаружил расхождений. При повторном запуске в новой среде `terraform plan` сначала предложит создать отсутствующие ресурсы.

Для доступа к веб-сервисам из хостовой системы применялись SSH-туннели, поскольку порты Docker опубликованы только на `127.0.0.1` гостевой Ubuntu. Контейнер WordPress использовался только для демонстрации: база данных не настраивалась.

## Скриншоты

Доказательства установки, проверки конфигурации, создания ресурсов, работы сервисов, списка Terraform State и эксперимента с configuration drift сохранены отдельно. В репозиторий следует добавлять только проверенные изображения, не содержащие секретов или личных данных.

## Безопасность и ограничения

- `terraform.tfstate`, `terraform.tfstate.backup` и каталог `.terraform/` не публикуются: Terraform State может содержать чувствительные данные в открытом виде.
- Файл `/tmp/xxx.txt` содержит демонстрационное значение и доступен только владельцу (`0600`). Его содержимое не выводится и не публикуется.
- Привязка портов Docker к `127.0.0.1` ограничивает непосредственный сетевой доступ к сервисам в гостевой ОС.
- Используемые образы и версия Nginx предназначены для воспроизведения учебного примера, а не для развёртывания промышленной системы.
