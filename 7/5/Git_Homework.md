# Задание 1 — базовые операции с Git

## Цель

Создать отдельный публичный репозиторий GitHub с `README.md`, клонировать его по HTTPS, настроить Git, отследить состояния `README.md` и изменения до/после добавления в индекс, выполнить коммит `First commit` и отправить его в удалённый репозиторий.

## Порядок выполнения и команды

**Статус: WIP — выполнение не подтверждено.** Следующие команды — план, а не журнал выполненных действий.

1. Создать публичный репозиторий на GitHub с опцией **Initialize this repository with a README**; подтвердить его URL.
2. Клонировать по HTTPS и перейти в каталог репозитория:

   ```bash
   git clone <HTTPS-URL-РЕПОЗИТОРИЯ>
   cd <КАТАЛОГ-КЛОНА>
   ```

3. Проверить/настроить настоящее имя и email. Перед применением глобальной настройки проверить существующие значения и влияние на другие проекты:

   ```bash
   git config --global user.name
   git config --global user.email
   # При необходимости, после подтверждения значений:
   # git config --global user.name "<НАСТОЯЩЕЕ ИМЯ>"
   # git config --global user.email "<EMAIL>"
   ```

4. Проверить исходный статус, изменить `README.md` и сравнить статусы и diff:

   ```bash
   git status
   # Изменить README.md редактором
   git status
   git diff
   git diff --staged
   ```

5. Добавить `README.md` в индекс, повторить проверки, создать коммит:

   ```bash
   git add README.md
   git status
   git diff
   git diff --staged
   git commit -m 'First commit'
   ```

6. Проверить имя текущей основной ветки. В официальном задании указано `git push origin master`; эту команду использовать только если ветка действительно называется `master`:

   ```bash
   git branch --show-current
   # git push origin master  # если основная ветка master
   # git push origin main    # если основная ветка main
   ```

# Задание 2 — файл .gitignore

## Цель

Создать `.gitignore`, проверить его статус, добавить его в индекс и прописать правила игнорирования любых файлов `.pyc` и всех файлов директории `cache`. Сделать коммит и push.

## Планируемое содержимое `.gitignore`

```gitignore
*.pyc
cache/
```

**Статус: WIP — выполнение не подтверждено.** Содержимое выше является примером требуемых правил, а не подтверждением наличия файла в репозитории. `*.pyc` игнорирует файлы с этим расширением, `cache/` — каталоги с именем `cache` и их содержимое.

## Порядок выполнения и проверки

1. Создать пустой `.gitignore` и проверить его статус сразу после создания.
2. Добавить `.gitignore` в индекс, проверить статус.
3. Записать в `.gitignore` правила из раздела выше, снова проверить `git status` и проиндексировать окончательную редакцию файла.
4. Проверить игнорирование тестовых путей, создать коммит и отправить его в удалённую ветку.

```bash
# После создания пустого .gitignore:
git status
git add .gitignore
git status

# После записи правил в .gitignore:
git status
git add .gitignore
git diff --staged

# Проверить на реально созданных тестовых путях:
# git check-ignore -v <ПУТЬ-К-ТЕСТОВОМУ-ФАЙЛУ.pyc>
# git check-ignore -v <ПУТЬ-К-ФАЙЛУ-В-cache>

# После проверки:
# git commit -m "Add gitignore rules"
# git push origin <ТЕКУЩАЯ-ВЕТКА>
```

**Примечание:** проверка `git check-ignore` для отслеживаемых файлов может отличаться от проверки новых неотслеживаемых файлов; для неё использовать новые тестовые файлы, не включённые в индекс.

# Задание 3 — ветки и слияние

## Цель

Создать ветку `dev`, добавить и неоднократно изменить `test.sh`, выполнив несколько коммитов и push; независимо создать `main.sh` в основной ветке, выполнить коммит и push, затем слить `dev` в основную через `git merge dev` с осмысленным сообщением. Ветку `dev` не удалять.

## Планируемая последовательность

**Статус: WIP — выполнение не подтверждено.** Команды приведены как план последующей пошаговой практики.

```bash
# Сохранить/проверить исходное состояние и имя основной ветки:
git status
git branch --show-current

# Создать и открыть dev:
git switch -c dev
# Создать test.sh, внести произвольное содержимое
# git add test.sh
# git commit -m "Add test script"
# Изменить test.sh, создать ещё коммит(ы) и несколько раз выполнить push
# после соответствующих коммитов; первую отправку сделать с -u:
# git push -u origin dev
# после следующего коммита: git push origin dev

# Вернуться в основную ветку (master или main по факту)
# git switch <ОСНОВНАЯ-ВЕТКА>
# Создать main.sh, добавить, закоммитить, отправить
# git add main.sh
# git commit -m "Add main script"
# git push origin <ОСНОВНАЯ-ВЕТКА>

# Слить dev в основную ветку, сохранив осмысленное сообщение merge-коммита:
# git merge dev
# В открывшемся редакторе написать осмысленное сообщение merge-коммита
# git push origin <ОСНОВНАЯ-ВЕТКА>

# Проверить граф и наличие dev:
# git log --graph --oneline --decorate --all
# git branch -a
```

**Контроль:** выполнить несколько коммитов и push в `dev`, отдельный коммит и push в основной ветке, затем merge. Если Git автоматически выполнит слияние без открытия редактора, проверить, что сформировался merge-коммит с осмысленным сообщением (при необходимости — заранее согласовать способ его создания). Не удалять `dev` после слияния.
