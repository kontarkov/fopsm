# Задание 1 — Jenkins Freestyle Project

## Цель

Установить Jenkins и Go, сделать fork указанного в условии учебного репозитория, подключить его к Jenkins Freestyle Project, запустить тестирование Go и сборку Docker-образа командами `go test .` и `docker build .`.

## Порядок выполнения и команды

**Статус: WIP — выполнение не подтверждено.** Следующие шаги — план, а не журнал выполненных действий.

1. Проверить рабочую систему и установить Jenkins по лекции либо официальной документации; предпочтительно не использовать контейнер для Jenkins в соответствии с условием задания.
2. Установить Go на машину, где работает Jenkins, и проверить доступность Go из среды сборки Jenkins.
3. Сделать fork учебного репозитория, указанного в задании, и ознакомиться с дополнительным материалом в нём. Зафиксировать фактический URL форка.
4. Создать **Freestyle Project**, указать URL форка в настройках Source Code Management (Git) и проверить доступ к репозиторию.
5. Настроить шаги сборки для запуска команд в каталоге исходников проекта:

   ```bash
   go test .
   docker build .
   ```

6. Запустить сборку и проверить реальные результаты тестов и Docker-сборки в Jenkins Console Output. Отдельно удостовериться, что Docker доступен процессу Jenkins, а не только интерактивному пользователю.

**Контроль:** успешное выполнение одной команды не доказывает успешность второй. Нужны подтверждённые результаты тестов и сборки образа на реальном Jenkins-стенде.

# Задание 3 — Nexus и публикация Go-бинарника

## Цель

Установить Nexus, создать репозиторий типа raw-hosted, изменить Jenkins Pipeline так, чтобы вместо Docker-образа собирался бинарный Go-файл, и загрузить этот файл в Nexus средствами Jenkins.

## Порядок выполнения и проверки

**Статус: WIP — выполнение не подтверждено.** Ни репозиторий Nexus, ни опубликованный файл, ни изменённый Pipeline пока не подтверждены.

1. Установить Nexus на выбранную машину, проверить доступность интерфейса и работоспособность сервиса.
2. Создать в Nexus **raw-hosted** репозиторий, проверить его настройки и адрес публикации.
3. Изучить `Dockerfile` учебного Go-проекта и определить команду, которой собирается бинарный файл. Не подставлять предполагаемую команду до изучения исходника.
4. Изменить Jenkins Pipeline из задания 2: вместо `docker build .` выполнять проверенную команду сборки Go-бинарника.
5. Настроить загрузку созданного файла в Nexus **из Jenkins**. Учётные данные хранить в защищённом хранилище Jenkins, не раскрывать их в публичном отчёте и Console Output.
6. Запустить Pipeline, проверить успешное завершение сборки и загрузки, затем убедиться в наличии полученного файла в raw-hosted репозитории Nexus.

**Команда компиляции из Dockerfile:** **[УТОЧНИТЬ ПО ФАКТИЧЕСКОМУ ИСХОДНИКУ]**.

**Изменённый код Pipeline:** **[ДОБАВИТЬ ПОСЛЕ ПРОВЕРЕННОГО ЗАПУСКА]**.

**Контроль:** успешная компиляция Go-файла не доказывает его загрузку в Nexus. Нужны доказательства обоих действий и наличия файла в репозитории.
